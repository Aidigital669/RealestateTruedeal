2. Database & Schema Migration Guide

Before deploying code changes to your other website, execute the following SQL scripts in your PostgreSQL database. All statements are non-destructive and idempotent (safe to run on existing production data).

1
Alter crm_leads Column Lengths to TEXT

Previously, fields like bhk, budget, and location were constrained to VARCHAR(50). During Excel/PDF bulk imports or bespoke buyer submissions with multi-line notes, Postgres threw "value too long for type character varying(50)" errors. Converting them to TEXT permanently resolves this issue:

-- Run this in PostgreSQL database: ALTER TABLE crm_leads ALTER COLUMN bhk TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN budget TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN location TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN property_interest TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN status TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN designation TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN residence TYPE TEXT; ALTER TABLE crm_leads ALTER COLUMN notes TYPE TEXT;
2
Ensure search_history Table Exists with Indexes

The unified search engine tracks user queries to prevent false autocorrects and calculate trending searches:

CREATE TABLE IF NOT EXISTS search_history ( id SERIAL PRIMARY KEY, query VARCHAR(255) NOT NULL, locality VARCHAR(100), bhk VARCHAR(100), price_range VARCHAR(100), intent VARCHAR(50) DEFAULT 'buyer', results_count INT DEFAULT 0, ip_address VARCHAR(100), user_agent TEXT, created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() ); CREATE INDEX IF NOT EXISTS idx_search_history_query ON search_history(query); CREATE INDEX IF NOT EXISTS idx_search_history_created_at ON search_history(created_at);
3
Ensure BusinessPurpose Tables for Commercial Suitability

Required for tagging commercial properties with commercial activities (e.g. IT office, bank branch, retail shop):

CREATE TABLE IF NOT EXISTS "BusinessPurpose" ( id SERIAL PRIMARY KEY, name VARCHAR(255) NOT NULL, slug VARCHAR(255) NOT NULL UNIQUE, "isActive" BOOLEAN DEFAULT true, "createdAt" TIMESTAMP WITH TIME ZONE DEFAULT NOW(), "updatedAt" TIMESTAMP WITH TIME ZONE DEFAULT NOW() ); CREATE TABLE IF NOT EXISTS "PropertyBusinessPurpose" ( "propertyId" INTEGER NOT NULL REFERENCES "Property"(id) ON DELETE CASCADE, "businessPurposeId" INTEGER NOT NULL REFERENCES "BusinessPurpose"(id) ON DELETE CASCADE, PRIMARY KEY ("propertyId", "businessPurposeId") ); CREATE INDEX IF NOT EXISTS "PropertyBusinessPurpose_businessPurposeId_idx" ON "PropertyBusinessPurpose"("businessPurposeId");
4
Property Dossier Metadata Structure (Embedded in Property.description)

Property-level privacy and custom configurations are stored within <!-- DOSSIER_DATA: {...} --> HTML comments inside Property.description. The system automatically preserves and merges these keys:

{ "hideName": false, // When true, displays synthetic title and hides builder name "hidePrice": false, // When true, displays "Price on Request" "hideDirectContact": true, // When true (DEFAULT), hides WhatsApp & Advisor desk on public page "hideBreadcrumbs": true, // When true (DEFAULT), hides top breadcrumbs bar "isSafe": true, // When true, prevents deletion during bulk delete "customCostSheet": { ... }, // Manual stamp duty, registration, and total outlay override "highlights": [ ... ], // Structured bullet points "connectivity": [ ... ] // Distance and commute highlights }
